# TeslaSpot

車（Tesla など）と Bluetooth でつながったら、スマホの **Wi-Fi アクセス ポイントを自動で ON** にする Android アプリです。
車は一度つないだ Wi-Fi を覚えているので、アクセス ポイントが ON になればそのまま自動で接続されます。

- 対応: Android 13 以降（Android 16 / 17 の Pixel を想定）
- 配布: GitHub Releases のみ（Google Play では配布しません。理由は[下](#google-play-で配布しない理由)を参照）

## しくみ

```
車と Bluetooth 接続 ──▶ CompanionDeviceManager がアプリに通知
                         │
                         ├─ ロック中 ──▶ 通知「ロック解除で ON にします」→ 解除を待つ
                         │
                         └─ 解除済み ──▶ ユーザー補助が設定を開き、スイッチを押す
                                          └ 見つからなければクイック設定のタイルを押す
                                          └ ON になったのを確かめてから元の画面に戻る
```

- **画面ロック中は操作できません**。Android の仕様で、ロック中は他のアプリの画面を操作できないためです。車に乗ってスマホのロックを解除した時点で動きます。
- 1 回の接続につき自動実行は 1 回だけです。失敗したときは通知が出るので、タップして手動で ON にしてください。
- 車から切断したときの OFF は、アプリの「**車から切断したら OFF にする**」で選べます（初期値は OFF）。
  - ON にすると、切断したときにロックが解除されていれば、設定を開いてスイッチを OFF にします。
  - ロック中に切断したときは何もしません。Pixel の場合、つながっている機器が無くなるとアクセス ポイントは自動で OFF になります（設定の「自動的にアクセス ポイントを OFF にする」）。

## インストール

1. [Releases](../../releases) から最新の `TeslaSpot-vX.Y.Z.apk` をダウンロードして開く
   - 「この提供元のアプリを許可」を求められたら、ブラウザ（Chrome など）に許可を出す
2. TeslaSpot を開き、上から順に設定する

### 1. 車を登録する

**先に車と Bluetooth のペアリングを済ませておいてください。**

1. 「車を登録する（Bluetooth）」を押す
2. 「付近のデバイス」の許可を求められたら許可する
3. **ペアリング済みの機器** の一覧から車を選ぶ（カーオーディオは 🚗 付きで先頭に並びます）
4. システムの確認画面で許可する

システムへの登録（CompanionDeviceManager）ができない機種では、「Bluetooth 検知のみ」で登録するかを聞かれます。
ユーザー補助が ON なら、この方法でも動きます。

### 2. ユーザー補助を ON にする

Android 13 以降、ブラウザからインストールしたアプリはユーザー補助が最初はグレーアウトしています。

1. 「アプリ情報を開く」を押す
2. 右上の **︙** →「**制限付き設定を許可**」（表示されない場合は、先に手順 3 を一度試すと出てきます）
3. 「ユーザー補助を ON にする」を押し、「ダウンロードしたアプリ」→ **TeslaSpot** を ON

### 3. 通知を許可する

ロック解除待ちと失敗のお知らせに使います。

### 4. テストする

「今すぐテスト」を押すと、設定が開いてアクセス ポイントが ON になり、アプリに戻ってきます。
うまくいかない場合は下の「うまく動かないとき」を見てください。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| テストで設定は開くが、スイッチが押されない | 設定画面に表示されているスイッチの名前（例: `モバイルホットスポット`）を「スイッチの名前」に入れて保存 |
| クイック設定で失敗する | クイック設定の **1 ページ目** にアクセス ポイントのタイルを置く |
| 車につないでも何も起きない | ログに「車に接続しました」が出ているか確認。出ていなければ、車の登録を解除してから登録し直す |
| ユーザー補助がいつの間にか OFF | 一部の機種は電池の最適化でサービスを止める。設定 → アプリ → TeslaSpot → バッテリー →「制限なし」 |
| 銀行アプリが警告を出す・起動しない | ユーザー補助を使うアプリが有効だと拒否するアプリがあります。その場合は TeslaSpot のユーザー補助を OFF にするしかありません |

画面の下にあるログで、どこで止まったかが分かります。

### 安全のための作り

- スイッチを押すのは、表示名が候補（「Wi-Fi アクセス ポイントを使用」「アクセス ポイント」など）と **完全に一致する行** だけです。「自動的にアクセス ポイントを OFF にする」のような別のスイッチを押さないためです。
- 押す前に OFF であることを読み取り、押したあと ON になったことを確かめます。ON/OFF が読み取れないときは押しません。
- 画面を読むのは「設定」と「システム UI（クイック設定）」だけです。内容の保存や外部への送信はしません。
- 通信するのはアップデートの確認とダウンロードのときだけで、相手は GitHub だけです。

## アップデート

アプリ画面の「アップデート」から、GitHub Releases の新しい版をダウンロードしてインストールできます。

- 画面を開いたときに自動で確認します（12 時間に 1 回まで）。バックグラウンドでは通信しません。
- 初回だけ、TeslaSpot に「この提供元のアプリを許可」が必要です（ボタンを押すと設定画面が開きます）。
- ダウンロードした APK の SHA-256 が GitHub の値と一致しないときは、インストールしません。
- **v0.1.0 にはこの機能がありません。** v0.1.0 からは、一度だけ Releases から手動で入れ直してください。

## Google Play で配布しない理由

- Google Play のポリシーでは、障がいのある人を支援する目的以外でユーザー補助 API を使うアプリは厳しく審査されます。設定の自動操作は認められない可能性が高いです。
- 違反と判定されると、同じデベロッパー アカウントの他のアプリにも影響することがあります。

## ビルド

```bash
./gradlew assembleDebug
```

`app/build/outputs/apk/debug/app-debug.apk` ができます。

## リリースのしかた

署名鍵 `release.jks` とパスワードの入った `keystore.properties` はローカルにだけ置きます（`.gitignore` 済み）。
**鍵をなくすと上書きインストールができなくなる** ので、パスワードマネージャーなどにバックアップしてください。

初回だけ、GitHub の Secrets に鍵を登録します。

```bash
base64 -i release.jks | gh secret set ANDROID_KEYSTORE_BASE64
```

```bash
grep storePassword keystore.properties | cut -d= -f2- | gh secret set ANDROID_KEYSTORE_PASSWORD
```

```bash
grep keyAlias keystore.properties | cut -d= -f2- | gh secret set ANDROID_KEY_ALIAS
```

```bash
grep keyPassword keystore.properties | cut -d= -f2- | gh secret set ANDROID_KEY_PASSWORD
```

その後は `app/build.gradle.kts` の `versionName` と `versionCode` を上げてから、タグを push します。

```bash
git tag v0.1.0 && git push origin v0.1.0
```

GitHub Actions が署名済み APK をビルドし、Releases に添付します。
